# Explicit KV Mode Implementation Plan

> **For agentic workers:** Use the established worktree, test-first implementation and an independent whole-branch review. Never edit the user's original checkout.

**Goal:** Implement issue #101 through measured layout choice, explicit KV mutations,
lookup, migration, bounded bulk/compaction and native client integration.

**Architecture:** Keep the existing coordinator/catalog publication authority and
strict append profile. Add mode-dispatched COW validation, interval membership and
a bounded sorted producer. Use native dependencies and shared reservations.

**Tech Stack:** C++23, Arrow/Parquet 25, pinned Iceberg/SQLite, Python SDK, ES modules.

**Spec:** ../specs/2026-11-12-kv-mode-design.md

## Global Constraints

- Existing append hashes and receipt versions 1/2 remain byte-identical.
- KV cannot bypass the coordinator, exact base, durable files, or outer COMMIT.
- Preserve retained history, owned-buffer lifetime, shared reservations and all three outcomes.
- Keep product code, dependencies and generated data in the managed worktree/build/scratch.
- English commit and PR text; publish a fork branch targeting official main.

## Review Focus

- Historical files removed from latest stay visible to old snapshots and held cursors.
- A no-op has a permanent receipt despite having no snapshot; lost COMMIT is unknown.
- Duplicate/non-first-column/UTF-8 keys have exact full-row semantics across source chunks.
- Scattered and retained-history pressure refuse bounded work without discarding old state.
- Migration/compaction cannot weaken append compatibility, uniqueness or publication checks.
